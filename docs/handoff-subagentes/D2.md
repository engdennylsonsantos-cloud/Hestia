# Tarefa D (continuação): validar, corrigir e commitar
Uma execução anterior escreveu o código da tarefa D (veja git status e git diff) mas NÃO tinha shell: nada foi validado nem commitado. Agora você tem shell (bash permite npm, npx, node, git add/commit/status/diff/log, ls, cat, grep, rg). Itens feitos: (1) grips do telhado em arco só nos cantos lógicos, (2) snap em Aparar/Dividir/Deslocar/Girar, (3) destino dx,dy em Mover/Copiar, (4) activateView só adiciona a aba se a navegação for aceita, (5) exhaustive-deps em ShortcutsConfigDialog.tsx.
Faça:
1. CORREÇÃO OBRIGATÓRIA no item 3: o usuário digita decimais com vírgula (português). Um número único como "2,5" DEVE continuar significando 2,5 m (como era antes). Um par dx,dy só vale com ponto e vírgula ("2;3", "2,5;3") ou com vírgula seguida de espaço ("2, 3", "2,5, 3,5" é ambíguo: nesse caso trate como par só se houver exatamente uma ", " com espaço). Ajuste o código e os testes para isso, e nunca mude o significado de um número único.
2. Rode npm run typecheck && npm run lint && npx vitest run. Corrija o que falhar, dentro do escopo dos arquivos já alterados. Se um arquivo passar de 420 linhas (max-lines), extraia código para arquivo novo.
3. Confira, lendo o diff, que cada item faz o que se propõe e que os testes testam de verdade (não são vazios). Corrija o que estiver errado.
4. Faça UM COMMIT POR ITEM (git add só dos arquivos de cada item; se um arquivo serve a mais de um item, agrupe os itens no mesmo commit e diga no relatório):
   1) feat(perimetro): alças do telhado só nos cantos lógicos
   2) fix(perimetro): comandos de modificar usam o snap do esboço
   3) feat(perimetro): destino de mover/copiar aceita dx e dy
   4) fix(vistas): só abre aba quando a navegação é aceita
   5) fix(ui): dependências do efeito na tela de atalhos
5. RELATÓRIO FINAL com os resultados reais de typecheck, lint e vitest (números) e a lista de commits.
